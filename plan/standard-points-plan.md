## 1. 实现依据与现状

标准依据是本目录的 `dlt69845-2017.pdf`：第 7 章决定接口类属性结构，附录 E 决定 OI 及实例的类型/倍率，附录 B 定义单位，附录 C 定义一致性位图，附录 D 提供独立报文例子。标准印刷页码比 PDF 页序少 3；下面均优先使用章节、表号定位。

已核对表 124～134 的电能、需量、分相量、功率模型，表 148～149 的冻结模型，附录 E.1/E.3/E.5/E.6 的常用对象，以及附录 C 的协议/功能一致性块。具体点位录入时继续逐项核对完整原始页面，避免把 PDF 提取中的断行、乱码或示例笔误写入代码。

参考的 dlt645 实现：

- `../dlt645/cpp/include/dlt645/model/type_definitions.h`：编译进库的名称、单位、格式和 DI 定义表。
- `../dlt645/cpp/src/model/data_item.cpp`：DataItemManager 初始化电能、需量、变量、事件和参数，并按 DI 查询/更新。
- `../dlt645/cpp/tools/generate_type_definitions.py`：从 Python 静态定义生成 C++ 表，启动时无需读取配置文件。

698 当前已有 `model::Data`、`model::Oad`、`ObjectSchema`、`ObjectRegistry`、`MemoryObject` 及普通/记录 GET 服务，但没有标准目录、递归值结构说明和工程值换算。沿用现有协议及 provider 框架，在其上增加目录与辅助接口。

## 2. 点位确定的边界

点位定义来自“标准 OI + 接口类属性 + 索引规则”；具体设备采集清单来自“设备型号/配置 + 标准目录 + 厂家资料”。主站使用目录生成请求，服务端将实际提供的对象注册到 ObjectRegistry；主站查表不需要本地注册 provider。

- 内置目录声明库知道某个标准定义，不代表远端设备支持，也不代表本地服务端已经提供数据。
- 普通点位使用完整 OAD。索引 0 返回整体，非零从 1 开始；费率数量、单相/三相布局等存在设备配置因素，不能无限展开或写死一个通用数组长度。
- 冻结/事件记录使用 OAD + RSD + RCSD；查询日期、行数和列集合属于运行时条件。
- 目录按 OI 和属性编号选择定义，另行解释完整属性字节中的特征及索引。当前 ObjectRegistry 用 `attribute & 31` 匹配 schema，随后把原始 OAD 交给 provider，并非按完整 OAD 建唯一键。
- 参数的 static/dynamic 分类不等于访问权限。标准允许的写入能力与应用授予的写入权限分别保存；生成运行 schema 时默认只读，方法只有绑定真实实现后才显式启用。
- GET 的本地事务成功、逐项返回 Data、Data 符合预期结构分别判断。DAR=4 可标记未定义；拒绝、超时、类型不符应各自保留，不能都当成不存在。

附录 C.1 描述 GET/SET/ACTION 等服务能力，C.2 描述电能计量、复费率、事件记录等业务功能，没有逐 OI 支持清单。功能位不能直接证明某个 OI 或属性存在。现有 `Session` 构造函数还会执行 `options.parameters.function.fill(0)`，第一阶段不依赖功能位过滤；第三阶段再解决其配置、协商和兼容策略。

当前方案只以 2017 PDF 为基线，不引入尚未核对原文的新版自描述接口。也不将“CONNECT 是唯一声明能力的机会”作为设计假设；对象的配置属性同样可提供数组规模、关联列等信息。

## 3. 第一阶段：14 个常用 OI

表中只列属性 2 的值；正式目录还包括各接口类适用的逻辑名、换算及单位等属性。`array<T>` 表示整体 Data 的标签为 array，元素标签为 T，不能直接注册成标量 T。

| OI | 名称 | 属性 2 数据结构 | 十进制倍率 | 单位/布局 |
| --- | --- | --- | --- | --- |
| 0000 | 组合有功电能 | array<Int32> | -2 | kWh；总、费率 1～n |
| 0010 | 正向有功电能 | array<UInt32> | -2 | kWh；总、费率 1～n |
| 0020 | 反向有功电能 | array<UInt32> | -2 | kWh；总、费率 1～n |
| 0030 | 组合无功 1 电能 | array<Int32> | -2 | kvarh；总、费率 1～n |
| 0040 | 组合无功 2 电能 | array<Int32> | -2 | kvarh；总、费率 1～n |
| 2000 | 电压 | array<UInt16> | -1 | V；A、B、C，单相为一项 |
| 2001 | 电流 | array<Int32> | -3 | A；A、B、C，单相为一项 |
| 2004 | 有功功率 | array<Int32> | -1 | W；总、A、B、C |
| 2005 | 无功功率 | array<Int32> | -1 | var；总、A、B、C |
| 2006 | 视在功率 | array<Int32> | -1 | VA；总、A、B、C |
| 200A | 功率因数 | array<Int16> | -3 | 无量纲；总、A、B、C |
| 200F | 电网频率 | UInt16 | -2 | Hz |
| 4000 | 日期时间 | DateTimeS | 不适用 | 不套用数值倍率 |
| 4001 | 通信地址 | OctetString | 不适用 | 保留原始字节 |

首批补齐的相关属性：

- 电能类：属性 1 为 OctetString 逻辑名、属性 3 为 ScalerUnit；属性 4 为扩展精度数组（有符号 Int64 / 无符号 UInt64）、属性 5 为对应 ScalerUnit，倍率 -4。设备模板显式选择是否使用扩展精度。
- 分相量、功率和频率：属性 1、属性 3；电流对象另有属性 4 零线电流 Int32，倍率 -3 A。
- 日期时间和通信地址：首批暴露属性 1、2。4000 的校时模式、精准校时参数和广播校时方法留到后续参数/方法支持批次，不宣称完整对象实现。

典型点位：

| 需求 | OAD |
| --- | --- |
| 正向有功总电能 | `00 10 02 01` |
| 正向有功费率 1 电能 | `00 10 02 02` |
| 正向有功总及全部费率 | `00 10 02 00` |
| A/B/C 相电压 | `20 00 02 01` / `20 00 02 02` / `20 00 02 03` |
| 总有功功率 / A 相有功功率 | `20 04 02 01` / `20 04 02 02` |
| 零线电流 | `20 01 04 00` |
| 电网频率 | `20 0F 02 00` |
| 日期时间 / 通信地址 | `40 00 02 00` / `40 01 02 00` |

电能费率点仅在设备配置的数量范围内展开。功率单相布局为“总、A”，三相布局为“总、A、B、C”；不自动补不存在的相别。

## 4. 第一阶段接口与文件设计

建议建立 `dlt698::standard` 命名空间，名称在实施时依项目惯例调整：

| 文件 | 职责 |
| --- | --- |
| `cpp/include/dlt698/standard/catalog.hpp` | 标准对象、属性、值结构、单位倍率和来源的公开模型；目录枚举、按 OI/OAD 查询、OAD 辅助构造 |
| `cpp/src/standard/catalog.cpp` | 14 个 OI 的不可变定义表及查询/校验；链接 core，不依赖网络会话 |
| `cpp/include/dlt698/service/standard_object.hpp` | 从选定目录属性生成 ObjectSchema，以及绑定 provider 的辅助接口 |
| `cpp/src/service/standard_object.cpp` | 生成只读 schema；可选的标准值结构校验适配器，复用原 IObjectProvider |
| `cpp/examples/standard_points.cpp` | 电压、电流、电能、通信地址的客户端查表和服务端内存模拟示例 |
| `cpp/tests/standard_points_test.cpp` | 标准定义、索引、结构和倍率验证 |
| `website/docs/protocol/standard-points.md` | 首批点表、典型 OAD、查表与绑定 provider 使用说明 |

元数据包含 OI、中文名、class_id、属性编号、顶层/元素类型、数组布局或结构字段、标准访问约束、记录标识、默认倍率/单位、标准版本及章节表号。动态长度同时记录来源（设备配置/实际值），并限制 OAD 的一字节索引及现有 Limits，避免不受限枚举。

拟提供的能力：

1. `objects()`、`find_object(oi)`、`find_attribute(oad)`：列出和查询内置定义；返回值的所有权及生命周期写入中文 Doxygen。
2. 按相别、总量、费率构造常用 OAD；非法布局/索引返回错误，不静默截断。
3. 校验 Data 的顶层标签、数组元素及结构字段。普通 ObjectRegistry 的手写 schema 行为保持兼容；标准绑定路径使用适配器增加严格校验。
4. `make_object_schema(...)` 从显式选择的属性生成只读 schema；`register_standard_object(...)` 绑定调用方提供的 provider，重复 OI 沿用现有拒绝语义，不覆盖。
5. 标量工程值采用“原始值 × 10^scaler”；原始 Data 始终保留。数组按元素处理，结构只换算数值字段，记录时间、逻辑名和地址不参与换算。Int64/UInt64 不默认转 double，给出保留原始整数及倍率的精确表示，浮点便利转换显式说明精度。

标准定义先用经过核对的 C++ 静态表作为单一来源，启动时无需读取外部文件。规模扩大后再评估类似 dlt645 的生成脚本；不在第一批引入第二份独立维护的 Python 点表。

设备模板保存选用的 OAD、接线方式、费率数、展示单位及访问策略。标准目录查询与设备采集模板分开：厂家私有 OI 继续通过现有手写 schema/provider 使用；若未来加入扩展目录，要求显式来源且不隐式覆盖 2017 定义。

## 5. 后续两阶段

### 第二阶段：扩充普通点位

- 按附录 E.1 补分相电能、四象限及视在电能；逐个确认符号类型和倍率。
- 按附录 E.2 补常用最大需量。属性 2 是数组，每个元素为“需量值 + DateTimeS”结构，时间不能被转成数值倍率。
- 按附录 E.3/F 补温度、当前需量、运行状态字及谐波；谐波类的属性 3 是 B 相数值组，倍率/单位在属性 6，不能套用普通量的属性 3 规则。
- 按附录 E.5 补表号、客户编号和常用参数；写入/校时方法需独立定义 provider 行为及权限，不能仅凭点表打开。
- 明确各批次覆盖的属性和方法，以“已定义元数据 / 已支持读写业务 / 已完成模拟”分别报告。

### 第三阶段：记录模板与可选能力筛选

- 首先实现日冻结 `5004` 和月冻结 `5006` 的只读查询模板；记录属性 2 声明 `record=true`，按配置的关联列建立 RCSD。
- 日冻结示例使用 `50 04 02 00`，时间定位列 `20 21 02 00`，电能列 `00 10 02 00`；日期由调用方传入。冻结时间与记录序号也是普通列定义，不能给每天生成一个虚构 OI。
- 复用 GetRecord、MemoryObject::bind_record 和已有分块收齐；模板只构造选择条件，真实历史存储由应用 provider 提供。模拟后端明确支持的 RSD 分支、记录上限、行序及快照生命周期，不声称完整选择器业务。
- 事件类逐个核对附录 E.4 的记录结构和关联对象，复用相同查询机制。通用历史数据库、周期冻结调度与事件检测不属于首批固定目录范围。
- 能力筛选先用协议一致性位确认能否发送 Normal/List/Record；GET List 不支持时按策略拆为普通 GET。记录服务不支持时返回明确的不支持结果，不退化成普通读记录表。
- 功能位配置若需要启用，先修改并测试当前清零策略；仅声明应用实际支持的业务能力。缺少功能信息时保留候选点，不能按全零位图删除所有点。
- 可选逐项 GET 验证设备点位，并保存 Data/DAR/事务错误和类型检查结果；请求由调用方显式发起，设置批量大小、超时及资源限制。功能位最多提供筛选提示，最终支持状态仍按设备文档和逐项响应确认。

## 6. 兼容、文档与验收

现有自定义 schema、MemoryObject 和 GET/SET/ACTION API 继续使用。内置目录不自动注册全部 OI，也不自动填充未知硬件值。现有示例中 `2000/属性2` 有直接模拟 UInt16 的用法；展示标准电压时改为 Array<UInt16>，读单相用非零索引。仅测试通用框架的任意 schema 可保留，但需注明它不是标准对象定义，避免混淆。

同步修订 `website/docs/protocol/point-model.md`：645 地址域为 6 字节；698 OAD 为 4 字节；说明 schema 的掩码查找与完整 OAD 传递；一致性块是服务/业务能力，不是 OI 支持目录。更新 coverage 中“未提供标准对象目录”的现状，并链接首批准确覆盖范围。

第一阶段验收：

1. 14 个 OI 均可列出并查询；每项具备准确名称、接口类、属性结构、倍率、单位及标准来源；OI/属性无重复。
2. 总量、费率、A/B/C、单相/三相索引正确；索引 0 与非零返回类型不同，超范围返回明确错误。
3. 电压 2413 对应 241.3 V，电流 1000 对应 1 A，功率采用 W 而非照搬 645 的 kW；负功率、有符号电能和扩展精度整数不丢失。
4. 不只是检查 array 标签：错误元素类型、结构错位、错误数组长度也能在标准路径识别；未知标准 OI 不妨碍通用 API 请求厂家点。
5. 内存客户端/服务端完成单项 GET、GET List 的 Data/DAR 混合响应；未提供的属性为 DAR=4，默认写入拒绝，重复注册不覆盖。
6. 对附录 D.3.1/D.3.2 已有通信地址及电压/电流向量做回归，补基于 PDF 独立期望值的电能/功率向量，不仅做编解码自循环验证。
7. 运行现有 core、connection、session、mutation、m4m5、serial_link、tcp（启用时）及 installed_consumer 测试；安装消费方调用新目录/标准绑定 API，验证静态和共享导出。
8. C++17 构建并保持 transport=OFF 可用；公开头文件及新增函数采用中文 Doxygen，重要实现含中文说明，UTF-8 保存，安装目标继续向 MSVC 消费方传递 `/utf-8`。
9. 新增/修改 C++ 文件用根目录 `.clang-format` 格式化；对项目自身源码执行 `clang-format --style=file --dry-run --Werror`，排除 third/ 和构建/生成目录。文档改动后执行网站现有构建检查。

第三阶段另验收：空记录、记录列宽/表头、时间筛选、分块收齐、查询资源上限、未声明 record、无处理器、功能位未知及非零 CONNECT 结果等行为。
