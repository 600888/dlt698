# M4/M5 使用与验收

更新：2026-10-07。M4 软件功能及 M5 两种分段、记录已实现。真实串口/RS-485 和独立设备互操作仍需设备验收；示例服务端只提供模拟数据。

## 示例分类

普通服务器优先使用 `cpp/examples/app/server.cpp`（`dlt698_server`），包含 `dlt698/app.hpp` 并链接 `dlt698::app` 即可直接设置数据和启动 TCP/串口。它发布标准频率 `200F`，默认 TCP 自动 LINK 登录，按 Enter 停止；原 tcp_server/client 的 `2000` 模拟目录配对示例保持独立。详见[托管入口](../website/docs/session/server.md)。

配对客户端为 `cpp/examples/app/client.cpp`（`dlt698_client`），连接、读取、断开均由高层入口处理；见[托管客户端](../website/docs/session/client.md)。

示例源码在 `cpp/examples/` 下按层次分四个目录：`app/`（托管两端）、`codec/`（编解码）、`service/`（对象服务，全部跑在内存通道上）、`transport/`（分层 TCP 与串口）。`transport/` 下的服务端与客户端各是一个独立程序，两侧共用 `transport/demo_device.hpp` 的模拟对象目录，可直接配对运行。

## 独立主站与终端

启用 DLT698_BUILD_TRANSPORT、DLT698_BUILD_EXAMPLES 后，bin 目录生成以下传输层程序：

| 程序 | 协议角色 | 链路建立 |
| --- | --- | --- |
| `dlt698_tcp_server` | 服务器 | `TcpListener` 监听，循环接受客户机直到时限 |
| `dlt698_tcp_client` | 客户机 | `TcpChannel::connect` 主动拨号 |
| `dlt698_rtu_server` | 服务器 | 打开串口 + `SerialLinkChannel` |
| `dlt698_rtu_client` | 客户机 | 打开串口 + `SerialLinkChannel` |
| `dlt698_master` / `dlt698_terminal` | 由宏决定 | TCP 监听或拨号，串口 |

TCP 配对验证（服务端可连续接受多个客户机）：

```sh
dlt698_tcp_server 0.0.0.0 6980 60
dlt698_tcp_client 127.0.0.1 6980 get
dlt698_tcp_client 127.0.0.1 6980 set 25
dlt698_tcp_client 127.0.0.1 6980 action 25
dlt698_tcp_client 127.0.0.1 6980 record
```

`dlt698_master` / `dlt698_terminal` 用于验证协议角色与 TCP 拨号方向相互独立：主站监听、终端拨入时先运行主站：

```sh
dlt698_master tcp-listen 127.0.0.1 6980 record
dlt698_terminal tcp-connect 127.0.0.1 6980 60
```

串口两端使用不同的真实端口/设备路径：

```sh
dlt698_rtu_server COM3 9600 60
dlt698_rtu_client COM4 9600 get
```

两端都提供模拟 OI=2000：属性 2 为可写 UInt16，方法 1 用 UInt16 参数替换模拟值并返回该值，属性 3 为一行时标/数值记录。record 示例使用 RSD=0、RCSD=0 全选；其他筛选与非匹配表头返回拒绝，由实际 provider 接入业务语义。客户端打印精确 Data hex 和原始 DAR。每次命令执行 CONNECT、请求、RELEASE 并关闭；服务端在对端关闭、Ctrl+C 或指定寿命到期时退出。RS-485 是半双工共享总线，服务端打开串口后直接应答，没有 accept 和 LINK 登录。默认字格式 8E1，通道加四FE 和 33 位软件时序。真实排空/手动 RS-485 方向 hooks 请通过 API 接入，CLI 未假定 USB 驱动或适配器具备物理排空保证。打开失败路径已测试，以上串口收发命令尚未在硬件执行。

## 心跳与时间标签

SessionOptions.heartbeat_seconds 非零时，协议服务器在预连接建立后周期发心跳；require_login=true 时先调用 async_link(login)。有在途 LINK 时延后发送，心跳无应答关闭通道并结束等待；自动重新拨号、重登录由应用决定。单次 async_link 的周期字段不改变自动周期配置。心跳 PIID 遵守同一隔离期，不绕过 64 个序号的资源限制。

request_time_tag 为客户机请求启用 TimeTag，calendar_clock 默认 UTC，也可注入相同基准的日历时钟。发送日历必须具体合法，禁止 FF 通配。允许间隔零不限制时差，秒/分/时/日按固定时长，月/年按日历并截到月末。过期请求被丢弃且不调用 provider；响应原样回传并由客户机检查。没有响应时，总事务超时关闭通道；写入/方法结果仍按原有副作用约定处理。

## 两类分段与资源

链路分帧负责一份 APDU 的原始片段。起始/中间片等待最近正确序号确认，末片按标准交换图直接交付；序号 0–4095 回绕。重复片重新确认而不重复拼接/提交，错序/变更方向不推进重组。fragment_timeout 控制确认等待，fragment_retries 为 0–16 次相同片段重发；reassembly_timeout 控制接收无进展的重组回收，重复片不延长它。确认重试或重组超时关闭通道，避免旧片进入新事务。

GET Next 负责可独立解析的完整属性/记录行单元，按行分块重复精确 OAD/RCSD，客户机校验并合并表头一致的连续行。重复记录 OAD 的查询保持整个记录结果边界，Session 禁用行合并。块号从零到 65535，不回绕；所有块保持原 PIID/优先级。错序/重复响应只诊断，总事务仍有超时；不自动重发应用请求。服务器错块号返回末块 DAR=10，没有快照时返回末块 DAR=11。一个单元超过单帧目标时，该块还可以链路分帧；超过协商 APDU 上限时返回异常，不能把一列 Data 的字节任意切成应用块。

每次 GET/Record 查询先获取拥有内存的快照，后续 Next 不再读取 provider。单份快照受 Limits.max_data_bytes 限制；每块受协商 apdu_bytes 和帧尺寸约束，客户机累计块字节/结果数受本地 Limits 限制。服务器快照在新 GET、释放、request_timeout 无 Next 或关闭后清理。目录锁外调用 provider，因此跨记录/跨查询的一致性必须由应用后端保证。

单会话最多一个在途事务、一个发送分帧、一个接收重组、一份 GET 快照及八个待发送 APDU，每个 APDU 另受字节预算限制。独立 LinkFragmenter/LinkReassembler/GetBlockTransfer 不创建线程或计时器，使用它们的调用方负责地址上下文和超时回收；Session 已接入上述管理。

## 本地证据

2026-10-07：MSVC 19.39 Release 共享/静态、MinGW GCC 15.1 Release 静态（开启 Asio）三组完整构建和 11 项 CTest 通过；MinGW 关闭传输的 8 项通过。新增库与 device/app 测试通过严格告警构建，完整现有回归使用普通告警配置。安装消费方验证 app 独立链接及原描述符、分帧、同步服务导出。MinGW Asio 线程配置已统一，TCP 测试恢复默认执行；详见[应用接口验收记录](../plan/application-api-plan.md)。

独立进程 TCP 验证两组：`dlt698_tcp_server` 连续接受 4 个 `dlt698_tcp_client`，get/set/action/record 四类命令各执行一次共 4 次成功，服务端日志确认登录成功；`dlt698_master`/`dlt698_terminal` 双向拨号分别执行四类命令，共八次成功。RTU 一对只验证了参数校验与打开失败路径，真实串口收发未执行。

m4m5 测试覆盖固定字段与 D.3.3 记录向量、全选择器分支、精确 Data 类型、嵌套预算、4095 序号回绕、丢失 ACK、重复/错序片、重组/心跳超时、快照取消/回收、DAR10/11，以及 GET Next APDU 再经链路分帧传输。软件测试和真实设备互操作分别记录在支持矩阵中。
