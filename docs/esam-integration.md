## 已实现的软件路径

`security::IBackend` 是每个 Session 独占的有状态接口。客户机调用 `begin_connect` 获得认证机制/材料，成功响应通过 `verify_connect` 后才建立关联；服务器调用 `accept_connect` 校验材料并返回标准 CONNECT 结果及 SecurityData。公共、口令、对称、非对称 CONNECT 的线格式已有模型，实际允许哪些机制由后端安全策略明确控制。

SECURITY-Request 支持明文/密文与 SID_MAC、RN、RN_MAC、SID 四类验证字段。SECURITY-Response 支持明文、密文、验证 DAR 以及可选 MAC/SID_MAC。它们使用 `encode_security` / `decode_security`，独立于内层业务 `Apdu`，无 PIID 和业务尾部。

安装 `SessionOptions::security_backend` 才对外声明安全能力位 31。默认 `protect_application=true`，关联后业务（含 REPORT、确认和 RELEASE）必须经安全封装；拒绝明文降级、嵌套 SECURITY、角色相反的封装、验证失败和不应被封装的 LINK/CONNECT。必须验证并解密成功才能调用对象/provider。认证失败不能退回公共连接。关闭、释放和析构清理后端状态，拒绝安全后端与预设关联组合。

五类 Data：MAC、RN、SID、SID_MAC、COMDCB 已有拥有型值模型和受限 codec。这些字段 codec 不自行生成随机数、计算 MAC 或解密。

## 厂商适配实现要求

继承 [IBackend](../cpp/include/dlt698/security/backend.hpp)，将八个操作映射到厂商 ESAM API，并通过 `SessionOptions::security_backend` 注入。库不包含厂商 SDK、不保存明文密钥，也不猜测命令号、密钥索引、算法模式或 MAC 覆盖范围。

实现须满足：

- 随机数由合规安全模块/随机源生成并按会话管理，校验对端新鲜度及重放状态。
- 验证对端认证材料、MAC/签名和设备身份，验证失败返回错误，不向业务交付明文。
- 明确 SID 与附加数据、RN/MAC 长度、填充/加密模式和签名/MAC 覆盖字段，严格遵循厂家接口及设备配置。
- 密钥保存在模块内；会话仅持有槽位/句柄引用。日志不记录密钥、口令、会话材料或未经许可的敏感报文。
- SDK 调用在会话执行器内有界、非阻塞；较慢硬件 I/O 需厂商适配层安排外部工作和结果准备，不能阻塞会话/回调等待同一执行器。当前 IBackend 是同步返回合约，不能直接塞入无界阻塞的 SDK 调用。
- `reset()` 幂等且不抛异常，清理随机数、会话密钥引用和重放状态；同一实例不得被多个 Session 共享。

服务测试中的 `TestEsam` 使用固定字节和 XOR，仅检查状态迁移、接口调用、验证失败、明文降级和释放清理，不能作为密码实现或现场安全验收证据。

## 需要提供的非敏感资料

| 材料 | 用途 |
| --- | --- |
| ESAM 厂家、型号、固件版本 | 确定模块命令和认证机制 |
| SDK 根路径、头文件、库/DLL 与 x64/x86 ABI | 实现实际适配、构建和加载 |
| API 手册/示例路径、错误码表、线程安全约束 | 确定密钥槽位、随机数、MAC/加解密和超时 |
| 模块连接方式和接口参数（SPI/UART/USB等） | 实现驱动生命周期及取消 |
| 目标设备型号、协议角色、安全策略、必需 OI/属性/方法 | 确定互操作和 provider 覆盖 |
| 测试凭据的受控文件路径或获取方式 | 本机读取测试身份/证书/槽位配置，密钥不贴聊天 |
| 厂商脱敏认证/SECURITY 正反例 | 建立独立字节及密码结果回归 |

测试凭据应由授权厂家/测试系统签发或配置；仓库不生成“可用 ESAM 密钥”，不将测试密钥、证书私钥或口令加入版本管理。
